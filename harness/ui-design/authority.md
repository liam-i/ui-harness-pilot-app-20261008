# 人工 UI 权威约定

在独立记录中填写并经项目负责人审阅；取得实际提交后由工程 Review 固定本文件的 repository／commit／path／SHA-256。离线检查使用[policy模板](policy.yaml.example)表达同一权威，`basis_refs`固定实际审阅依据；不得仅抄YAML名字便声称已核身份。当前观察按[共用observer](current-check.md)执行；不修改需求层project config。

| 事实 | 必填内容 |
| --- | --- |
| 权威 | 实际仓库位置／remote、ref、决定目录、已经存在的历史起点提交 |
| 责任 | 可批准、发布、撤回的人与角色；AI可执行的整理和发布范围 |
| 身份依据 | 真实会话、平台审阅或签认的留存方式；YAML名字不能证明身份 |
| 历史保护 | 包与批准不可覆盖，决定追加；禁止删决定、同ID换字节、未经审阅更换起点 |
| 留存 | 分支／固定对象保护、完整Git bundle或存储、二进制、保留期与恢复责任 |
| 与工程权威关系 | 明确独立或相同；相同也须核对实际SHA，不能由业务目标未变推断UI未变 |

在实际 Propose、开始／恢复实施、Merge、scope 接纳和发布等依赖动作前，人工重新读取这里声明的 ref，记录实际 SHA、时间、原始查询及从起点可达的决定历史。检查批准及全部依赖的撤回适用性；新增修订本身不撤销旧消费者。

观察记录保存在消费者的阶段证据中，避免为记录观察再推进被观察的 UI ref。网络／仓库不可读或对象不齐时记录 unknown 并停止依赖动作；已经恢复的旧快照仅可作历史审计。UI当前许可也不能代替工程阶段授权。

本地试点可用已声明的独立Git仓库和ref，不声称具有托管分支保护。交接前保存完整bundle和实际媒体，在第二副本验证恢复；删除临时仓库前确认受控证据完整。观察、包恢复和工程回退是不同操作：恢复UI指针不会自动回退应用代码。
