# Figma 浏览器制作与文件交付

这条路线使用已登录浏览器中的原生画布、图层与组件，最后交付[共同固定包](../README.md)。已有依据仅覆盖限定浏览器制作、编辑、保存源版本、原生文件与媒体导出、独立恢复；不证明 Figma MCP、任意账号权限或版本锁定导出 API 可用。目标项目保存自己的工具观察与实际结果，不把参考案例的批准移用过来。

## 1. 选定文件和权限

在项目已授权的账号中打开实际文件，核对账号、团队／Drafts、文件 key、页面及读写权限。只读接收走 A：请提供方交付完整文件；B 制作需要明确的草稿写入范围。没有写入或导出权限时停止相应操作，已有完整源可沿[文件路线](files.md)接续，不换账号或自动安装 MCP。

在包外制作记录保存文件 URL/key、页面及关键 Frame／组件 ID、实际操作者、观察时间、Brief 位置和导出权限。URL 是溯源信息，不能代替固定源文件。先按 [authority.md](../authority.md)确定真正的产品／UI 审核者与工程负责人。

## 2. 制作、回读和迭代

按 Brief 建立画面与状态，使用实际图层／组件编辑或本次明确选用的制作能力。若通过输入框发送提示词，发送前回读首尾和完整状态清单；长提示词被截断时分成明确连续的请求，确认本轮范围完整后再发送。看到“任务已开始”只证明已受理。

制作结束逐项选中原生节点，核对 Frame 尺寸、安全区、自动布局、文本、字体／字间距、组件及实例关系。截图不证明对象可编辑。将反馈、修改位置及回读结果记入同一制作记录；缺状态或控件碰到系统栏时在原稿修正，再核对全部受影响尺寸与字号。

## 3. 固定同一份源并完整导出

1. 完成候选源审阅后保存具名版本，记录实际版本 ID／链接、保存时间及节点清单。与协作者约定本轮导出期间暂停编辑。
2. 重新打开该版本核对节点和样式，再确认用于导出的当前画稿与该版本相同。浏览器导出界面可能导出当前编辑视图；没有验证版本固定接口时，不能声称“用版本 ID 锁定了导出”。若无法证明一致，停止并重新选定、保存和导出。
3. 导出原生 `.fig`、全部画面／状态参考、tokens 和必需运行素材。记录每项节点、文件名、格式、倍率／尺寸、字节数和 SHA-256；为同名 Frame 明确唯一文件名，不能让下载覆盖掩盖缺项。
4. 导出后再次回读源版本、关键节点与文件集合。期间有修改则整批重新核对，保留旧候选记录；不能混用不同批次的源、图与 tokens。

`.fig` 是可编辑源的留存；PNG/SVG 是参考或运行资源，两者不能互相代替。SVG 必须符合[静态媒体子集](../data-contract.md#包闭包与媒体)；工程需要的字体／图片应完整交付并保留许可，不能依赖登录态、临时 URL 或本机缓存。

## 4. 在独立草稿恢复

将导出的 `.fig` 导入另一个明确授权的恢复草稿，核对页面、组件／实例数量及关键原生文字属性；从恢复稿重新导出约定文件，与候选清单逐项比较。恢复草稿只作验证，不替换制作权威。发现不可编辑、缺组件、图不齐或摘要变化时，保留差异并回到步骤 2／3；不要默认将变化解释成无影响。

回读与文件比较通过后，将这次源和导出物纳入 `manifest.yaml`，用 `sources.md` 说明实际观察、导出办法及限制，按[人工清单](../manual-checklist.md)形成 D 和闭包报告。**到此仍是待审候选**：真人查看最终 D 后才能保存 A，工程再沿[无需求层](../no-requirements.md)或[需求层](../requirements.md)消费。

## 失败与接续

| 现象 | 停点与恢复 |
| --- | --- |
| 未登录、只有查看权限、导出受限 | 保存可见能力；由账号／文件负责人恢复权限或提供完整文件，不伪造导出 |
| 请求或下载被截断、缺原生源／图 | 保留坏副本，重新取得同一源的完整内容，核对数量、格式、尺寸和摘要后再形成 D |
| 导出过程中源发生改变 | 中止该批，重新保存版本并一致导出；已批准内容变化必须用新修订与新 D/A |
| 工具不可用，但已有完整固定包 | 按原 A→D 恢复和 current 检查接续；只有截图或活动链接时仍停在缺件处 |
| 自动检查通过 | 仅完成相应结构／字节检查；不自动产生设计批准、原生验收或 Apply 权限 |
