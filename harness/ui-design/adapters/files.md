# 本地文件设计与取包

适用于团队导出文件、公开成品的受审接收，以及 AI 本地 SVG／HTML 等设计源。两种来源都使用 [Brief](../brief.md)、[handoff](../handoff.md) 和共同 Schema；本适配不连接设计账号，不改变批准和工程授权。

## A：接收现有设计

读取来源、版本、许可、界面／状态与完整素材；确认导出期间源未混版。公开成品可以用作输入，但作者、许可证或下载成功不是本项目批准。按实际范围补齐交接信息，经源语义审阅后导出完整 D，再交实际审核人批准该 D。缺文件或状态时交回提供方，不替其猜测。

## B：本地制作与迭代

在授权草稿目录制作可编辑源及预览。SVG／HTML 可表达方向与状态，但须补充原生／引擎单位、安全区、交互、素材映射及适用预算。按真实反馈修改并记录处置，确认候选源后完整导出 D；最后一次导出的字节仍须人工审核。已有获批包没有变更需要时，直接核对复用，不制造新版本。

完整制作、最终审核及发布步骤见 [人工清单](../manual-checklist.md)。`producer.mode` 只记录来源，下游不分两套验收。D 阶段预检不得虚构 A；共同消费检查器在真实批准已存在后使用。

## 获批包导出

在已复制 `harness/ui-design/` 的业务副本中，按 [离线安装](../offline-check.md#安装与前提) 准备锁定 Python，再取得经过原工程审阅的固定快照。`repositories` 指向完整本地 Git 副本；当前动作另按 [current](../current-check.md) 核对权威。

```bash
# output 的父目录已存在，目标目录尚不存在，且位于输入仓库之外。
"$UI_DESIGN_PYTHON" -B harness/ui-design/adapters/fixed_files.py \
  --root "$PWD" --context /absolute/path/to/ui-snapshot.json \
  --output /absolute/path/to/new-handoff
```

适配器先调用原共同库，全部输入通过后，从固定 Git 对象导出所有所选包及递归依赖。产物为 `packages/<unit>/<release>/` 和 `receipt.json`；清单、文件均保持原字节。收据保留检查结果、固定引用及适配器摘要，不是新批准、规则身份或运行 E。输入的未提交修改、活动设计稿和最新分支不会被混入。

本适配器仅处理 **Git 中完整存储文件的包**。已声明外部媒体／LFS 的包即使共同验证通过，也明确拒绝本适配导出；应由其原媒体交付路径提供完整材料，不能删声明使其通过。原共同 checker 对外部媒体的能力不受影响。

产物是供查看和导入的工作副本，不是完整 Git 备份；权威历史、A、policy、bindings 和外部引用继续按原合同留存与恢复。仅有这个导出目录不能重放 current 或历史决定检查。工程开始／恢复前仍调用原动作入口，不能用旧收据放行。

## 失败与重试

- 检查失败／UNKNOWN：返回非零及完整诊断，不创建输出目录，不启动工程。
- 输出已存在或位于输入仓库内：拒绝，不覆盖旧交付或写入权威。
- 输出过程中出现磁盘等错误：返回非零；仅当最后写成的收据存在且本次退出为零时导出成功。保留失败目录用于检查，重试选择新的输出目录；不承诺并发写入或掉电事务。
- 素材或批准确需改变：回制作与人工决定，生成新 D/A，不改已发布包。
