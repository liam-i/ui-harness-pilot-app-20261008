# Design Brief

这是待填写模板；未填内容、身份和验收不能视为已确认。

## 需求与范围

- 用户任务／目标：填写本轮任务。
- 固定需求来源：填写 repository、完整 commit、path、SHA-256；有需求层时引用确切 R 修订与 AC，无需求层时引用真实需求材料或已确认任务。
- 纳入／排除：列出本轮界面、流程与行为边界；视觉修订不能暗增业务承诺。
- 工程起点：仓库、提交、实际技术栈、相关组件与资源位置。
- UI 适用性：required／reuse／not-applicable、依据及审核记录；复用时固定原批准并复核当前适用性。

## 平台与验收分母

| 项目 | 本轮约定 |
| --- | --- |
| 平台与单位 | OS／引擎、pt／dp／像素换算、语言、字体与方向 |
| 尺寸与安全区 | 具体参考尺寸、设备、系统栏、缩放／锚点 |
| 必需画面与状态 | 稳定 screen/state ID；关键返回、关闭、取消与异常 |
| 输入与易用性 | 触控、键盘、返回、字体缩放、辅助技术的适用范围 |
| 生命周期 | 前后台／恢复的适用行为及原义务出处 |
| 预算 | 本轮适用性能／资源门槛及来源；不适用说明原因 |
| 运行验收 | 构建入口、实际设备／引擎、数据、独立 expected 与判定方法 |

## 来源与责任

记录原素材身份、许可、制作源与工具观察。已有 AST/DAS 只引用原 owner；没有这些身份时不伪造。新输出由 UI 清单唯一登记。

记录实际产品／UI 审核者、工程负责者、验收者、包发布和撤回责任；允许一人兼任，但不能伪造独立审查者。AI 制作不构成真人批准。

## 待决问题

逐项记录对象、原因、影响范围、负责人和恢复条件。影响当前消费的 blocker 未解决不能批准；确实不适用的维度写明依据，不把 unknown 当作通过。
