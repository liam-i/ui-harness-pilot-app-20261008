# UI 人工交付与消费检查

适用于[共同合同](README.md)。每次记录实际执行者、日期、对象、证据、结论和未验证范围；空勾选框不代表已执行。

## 1. 固定输入并制作

- [ ] 从真实需求与代码确认 Brief、screen/state 分母、原工程入口及授权。业务冲突回原 Q／R／RC或需求决定，不在画稿中改变承诺。
- [ ] A 接收确认稿与来源，不强制重新设计；B 在授权草稿中制作、回读并记录反馈、修订和处置。无有效团队批准时仍交当前审核人确认，来源身份不代替批准。
- [ ] 固定实际技术栈、素材许可、设备和适用预算；原型可审阅但不能充当原生／引擎运行验收。
- [ ] 输出同构 Brief、handoff、tokens、画面／状态、必需资源及清单；没有工具账号可以用本地文件生产。

## 2. 内容 D 与批准 A

- [ ] 内容先提交D。清单不列自己；从D读取清单与所有列举文件，逐项核对SHA-256、大小／格式、用途和完整文件集合；拒绝路径外逃、重复身份、未登记文件及活动链接作为必需内容。
- [ ] 递归恢复共享包批准、D及媒体，检查依赖无环。已有AST/DAS保持原owner；新UI输出只由UI清单登记。
- [ ] 形成完整闭包报告并固定；报告列出D、清单及所有文件／依赖／外部对象，不能只有“已检查”或LFS指针摘要。
- [ ] 人工看最终导出画面、状态、限制及完整摘要；保存真实actor／角色、时间、范围、原决定和证据。缺批准或有消费blocker停止，不由AI代签。
- [ ] 在后续提交A保存绑定D及闭包的批准，A引用已经存在的对象，不写自己的未来SHA。审批证据同A保存时用文件路径和字节摘要，避免循环。
- [ ] 发布到已声明权威并保留对象；独立副本恢复A→D及完整依赖。制作源被修改或不可用时仍取相同字节，缺件不换最新版。

## 3. 沿原工程入口消费

| 入口 | 保存方式 | 必须保留的边界 |
| --- | --- | --- |
| 需求层候选 | 原engineering context／asset_uses固定完整文件；人工sidecar绑定实际贡献、A和覆盖 | 设计资料先独立受审进入target；重读目标再走原dispatch和规划，不扩严格Trace字段 |
| 需求层已有／外部scope | 原delivery-map的真实endpoint贡献＋Review/E固定引用 | 只核交付不暗中实现；确需改工程先Tiny／Standard分流，不造空C／Change |
| 独立Tiny | 原task/PR及已有tiny_association／任务记录的固定引用＋Review/E | 不补Tasks或G2/apply，不绕未完成Standard义务；纯技术工作不造R/AC |
| 无需求层Standard | 当前Proposal/Design保存同等固定绑定，原唯一Tasks做实现与验收 | 不安装需求层、不造BL；Propose、完整规划Review和Apply各核原授权 |
| 无需求层Tiny | 原任务／PR保存同等固定绑定 | 原Tiny边界仍成立，不因视觉改动小就自动Tiny |

- [ ] required／reuse保存完整A引用、当前覆盖和允许差异；not-applicable保存具体受审依据。不能因缺包、缺工具或未批准改判无UI影响。
- [ ] 按[离线检查](offline-check.md)保存固定快照、规则身份、真实退出码与完整JSON；历史PASS只证明所选时点，不替代下一项current与原工程审阅核对。
- [ ] 按[当前观察](current-check.md)和[权威约定](authority.md)重新观察当前UI决定，保存policy固定引用、remote/ref、实际SHA、历史及原始证据；current未知停止，不借historical通过放行。
- [ ] 同时核对原业务目标、控制、依赖、有效请求和阶段停点；UI人工通过不授予Apply、Merge或发布。
- [ ] 当前Design解释组件／资源映射，唯一Tasks关联实现与验收。UI无业务变化不机械重签BL；业务变化走原需求／RC。

## 4. 运行验收与回退

- [ ] 实际运行资源进入原工程目录，在构建中使用；原型、活动设计源与包目录不能是运行时依赖。转换保留输入、参数和输出摘要。
- [ ] 行为任务使用项目TDD；已有行为补测不伪造RED，纯静态资源采用适用检查。保存命令、退出码、用例数、代码状态、设备及原始输出。
- [ ] 在本轮真实产品与选定设备／引擎核对状态、交互、布局、资源和预算，保存截图／视频、人工结论、差异及运行E。原型截图与构建成功不能替代交互检查。
- [ ] 按原Review、归档、最终检查与交付授权收尾；把UI事实引用到原证据中，不创建第二套任务台账。
- [ ] 包／批准错配、缺件、工具不可达：保存原错误，固定闭包可用则继续相同输入；缺必需对象停止。修复后从原停点重核，不能静默换包。
- [ ] 视觉修订产生新的D/A，工程负责人选择消费者并重评原Review／请求／E。撤回追加决定并说明旧消费者适用性；保留历史，停止被禁止的消费。
- [ ] 工程回退沿原流程，核对实际代码和构建；设计指针回退不等于产品回退。中断先查实际结果，不重复批准、归档或已完成操作。
